## 三、速度：双方默认都是 20 线程

| 场景 | Halcon 17 | 我们 | 倍数 |
|---|---|---|---|
| 20 线程 | **6.7~7.3 ms** | 13.4~16.8 ms | 2.0~2.5× |
| 各限 1 线程 | 13.4 ms | 44.0 ms（优化前） | 3.3× |
| 扩展性（我们） | 13.4 → 6.7（2.0×） | 44.0 → 23.3（1.9×） | 双方的并行效率相当 |

**单线程/多线程的倍数几乎一样**，说明差距在"单位工作量效率"，不在并行度。

### 我们的耗时拆解（优化前）

```
pre 2.3 | coarse 3.4 | refine 17.0 | subpix 2.8   = 20~25 ms
```

refine 占 72%，而 refine 内部：

| 层 | 画布 | 建旋转模板个数 | rotTpl | 打分 score |
|---|---|---|---|---|
| 3 | 28×29 | 41 | 0.71 ms | 0.34 ms |
| 2 | 55×55 | 28 | 1.24 ms | 0.26 ms |
| 1 | 107×108 | 30 | 3.66 ms | 0.97 ms |
| 0 | 214×214 | **15** | **6.76 ms** | 1.84 ms |

**建模板的开销是打分的 4~8 倍**。整次搜索要建 **114 个**旋转模板，
每个（214×214 画布）成本实测：

| 操作 | 单次 |
|---|---|
| `warpAffine` 灰度（INTER_LINEAR） | 0.246 ms |
| `warpAffine` 掩膜（`INTER_NEAREST`） | 0.090 ms |
| 两遍融合填充 tm/mk/st2 | 0.064 ms |
| 合计 | **≈0.40 ms/角度** |

Halcon 不做这件事 —— 它在评分时按需对模板做反向采样，不生成整块旋转画布。

## 四、本次已做的优化（+30%）

### 1. 融合 `buildRotTemplate`（无损）

原来是 `countNonZero / convertTo / convertTo / mean(masked) / subtract /
setTo(比较临时图) / mul + sum`，**8 遍整幅画布 + 2 个大临时图**，每角度一次。
改成两遍普通扫描（先求有效区均值，再一次性填 tm/mk/st2/row-span），无临时图。
顺带把 `buildRowSpan` 也融进去，省掉单独一遍。

精度：`ncc_selfcheck` 误差从 6.55e-08 降到 **2.32e-08**（更准了）。

### 2. 收紧进入 level-0 的候选数（4 → 2）

level-0 的旋转模板最贵（214×214，0.45 ms/个）。原来 4 个候选 → 15 个模板（6.76 ms），
现在 2 个候选 → 10 个模板（4.29 ms）。同时 level-2 从 8 收到 4。

效果：搜索 19.6~20.4 → **13.4~16.8 ms**。

风险已用数据排除：case1 7/7 命中、分数 0.991/0.995/0.993/0.897/0.894/0.901/0.890
**与优化前逐位一致**；旋转真值 7/7 不变。

## 五、还能继续缩小的空间（未做）

| 方案 | 预计收益 | 代价 |
|---|---|---|
| **每个角度用紧包围盒画布**（214×214 → 约 154×148） | rotTpl 再快 ~1.8× | 需改 `scoreAtPrepared`/span 的偏移逻辑，中等重构 |
| **缓存旋转模板（thread_local LRU）** | 连续帧时 rotTpl →≈0，**批量/视频场景约 2 倍** | 每线程几 MB 内存；单帧首次仍慢 |
| `fillConvexPoly` 代替掩膜 warp | 每角度省 0.086 ms（约 20%） | 边界像素可能差几个，会动到 1.000000 的精度断言 |
| 粗层用 FFT | 粗层 3.4 ms → 1 ms 量级 | 只省 10%，且与我们「逐角度卷积」的架构冲突 |

**最划算的是「缓存旋转模板」**：实际产线是连续图流，角度几乎不变，
第二帧起 rotTpl 基本归零，预计 13~17 ms → 7~9 ms，就与 Halcon 持平了。
但它会引入每线程内存开销，且要保证不破坏「`findNccModel` 是 const 可并发」的承诺
（需用 thread_local）。

## 六、2026-11-14 已落地：旋转模板跨帧 LRU 缓存

第五节规划的 LRU 已实现（`NccMatch/NccMatch.cpp` 的 `Impl::rotCache`）。
没有用 thread_local，而是复用形状匹配器已验证的更简单安全的模式：
**成员级 `unordered_map` + 串行预建 + 并行只读 + 满则整体清空**。

### 6.1 设计

- key = `(level, angleIdx)` 打包成 `uint64_t`；value = 完整 `RotTpl`
  （零均值模板 `tm`、有效域 `mk`、`st2`、`nValid`、行区间 `c0/c1`）。
- 旋转只依赖**模型**、与搜索图无关，所以同一 `NccMatcher` 对象在多次
  `findNccModel()` 之间可以直接复用——这正是视频/产线连续帧的场景。
- 缓存只在 refine 的**串行预建段**写入（`getRotTpl`），后面的
  `parallel_for_` 只持有裸指针读取，无锁、无数据竞争，不破坏
  「`findNccModel` 是 const 可并发」的承诺。
- 容量 = 所有层角度网格总数（同模型连续帧不会溢出）；`createNccModel` /
  `readNccModel` / mask 恢复时整体清空，杜绝陈旧数据。

### 6.2 正确性（无损，逐位验证）

同一 360° 模型、同一张图，LRU 版与旧版的 12 个检测结果
（score/x/y/angle）用 `Compare-Object` 比对**完全一致**，自匹配仍报 1.000。

### 6.3 实测加速（test2，同进程连续帧，preprocess+search 口径）

| 模型 | 旧版 | LRU 热帧 | 提速 |
|---|---|---|---|
| ±10°（21 poses/层） | 10.79 ms | **7.7 ms** | ~29% |
| 360°（360 poses/层） | 31.0 ms | **15.7 ms** | **~49%（近 2 倍）** |

debug=2 分段计时显示 360° 模型 level-0 的 rotTpl 从冷帧 8.25 ms 降到
热帧 **0.00 ms**，整帧 search 28.86 → 12.72 ms。

### 6.4 与 Halcon 的最新位置关系

360° 模型、同一张 992×992 图、同参数（minScore 0.3、12 matches）：

| | 冷帧（首帧/换角度） | 热帧（缓存命中，产线常态） |
|---|---|---|
| 本项目 NCC | ~32.9 ms | **~12.7 ms** |
| Halcon 17 NCC（32 位，仅 find） | 19.8~26.3 ms | —（Halcon 内部也有缓存，未暴露） |

- **冷帧**仍比 Halcon 慢（我们要物化旋转模板，Halcon 按需反向采样）。
- **热帧（实际产线连续图流）本项目 ~12.7 ms，已快于 Halcon 冷帧的 ~20~26 ms**，
  达成第五节「与 Halcon 持平/反超」的预期。
- 单张一次性任务（每次新进程、角度全变）缓存命中率低，收益有限；
  缓存的价值在**长生命周期 matcher + 连续帧**，这正是部署形态。

### 6.5 代价

- 内存：缓存持有所有用到的旋转模板。360°/96×96 模型实测缓存约
  24.5 MB（358 条目），可接受；对更大模型或更小角度步长，占用会
  增长但仍在个位数~两位数 MB 量级。
- 首帧/换模型仍需付一次全量构建成本（冷启动不变慢，只是不加速）。

## 七、2026-11-14 test2 200 张抽样：NCC 四器同批对比

> 第六节是「同一张图、换角度」的单图深挖；本节是**批量**结论：
> `dataset/test2` 200 张抽样（5 个日期），四个匹配器（本项目 shape/ncc ×
> Halcon shape/ncc）同模板同参数一次跑完。Shape 侧结论见
> `docs/ShapeMatch-vs-Halcon.md` 第十五节；原始逐图数据 `_ai_tmp/cmp200.csv`，
> 交接记录 `docs/test2四器对比-进度-2026-11-14.md`。

### 7.1 抽样与真值构成

| 日期 | 抽样数 | NCC 命中（≥0.9）本项目 / Halcon |
|---|---|---|
| 2024-05-07 | 40 | 0 / 0 |
| **2024-05-15** | **20** | **10 / 10** |
| 2024-05-16 | 45 | 0 / 0 |
| 2024-05-20 | 45 | 0 / 0 |
| 2024-05-21 | 50 | 0 / 0 |

即 **10 张真阳性 + 190 张真阴性**（190 张已用 Halcon 360° + 尺度 0.8~1.25 +
minscore 0.6 复核过，确实没有菱形 fiducial）。参数：±10°、minScore 0.3、max 12、
overlap 1.0；本项目 `NccDemo`（x64 AVX2，计时含 preprocess），
Halcon `find_ncc_model`（**x86 SSE2**，只算搜索）。

### 7.2 分数：r = 0.998，几乎等价

| 分位 | 本项目 | Halcon |
|---|---|---|
| p10 | 0.658 | 0.657 |
| p50 | 0.691 | 0.696 |
| p90 | 0.701 | 0.702 |
| 无检出 | 0 | 0 |

- 相关系数 **r = 0.9982**（n = 200，双方都有有效分数）。
- 10 张真阳性均值：**0.9929 vs 0.9934**，差 **0.0005**。
- 直方图（张数）：`[0.5,0.6)` 7 / 6、`[0.6,0.7)` 148 / 139、`[0.7,0.8)` 35 / 45、`[0.9,1.01)` 10 / 10。

> **实操注意**：190 张无目标图的 NCC top-1 就落在 **0.65~0.72**，真阳性 ≥0.98，
> 两者有 0.26 的间隔但没有"低分区"缓冲。所以 NCC 的判定阈值**不能沿用 0.7**
> （会把一批负样本判成命中，十四节 14.4 的 4 张 0.699/0.700 正是这个边界），
> 建议 **0.85~0.90**。这一点与形状匹配相反（Shape 负样本 <0.53，0.7 很安全）。

### 7.3 位置 / 角度：0.11 px、0.09°

| 指标 | NCC（本项目 vs Halcon） | 对照：Shape（同批同图） |
|---|---|---|
| 平均位置差 | **0.113 px** | 0.619 px |
| 最大位置差 | 0.121 px | 0.689 px |
| 平均角度差 | **0.085°** | 0.112° |
| 最大角度差 | 0.150° | 0.270° |

全 200 张实例数一致性：**198/200**（本项目 2394 个 vs Halcon 2400 个），
真阳性图双方都报 12 个。**这已经是"逐图一致"级别**，比 Shape 的 35/200 干净得多
（Shape 那个低值主要来自无目标图上噪声峰顺序随机，不代表能力差）。

### 7.4 速度：1.36× 差距（Shape 是 3.12×）

| 指标 | 本项目 | Halcon | 倍数 |
|---|---|---|---|
| p50 | 13.88 ms | 9.99 ms | — |
| **mean（200 张）** | **14.21 ms** | **10.44 ms** | **1.36×** |
| 双方都 ≥0.7（n=45） | 14.21 ms | 10.34 ms | 1.37× |
| 双方都 ≥0.9（n=10） | 12.51 ms | 9.65 ms | 1.30× |

- Halcon 侧是 **32 位 SSE2**，本项目 **64 位 AVX2**；我们的 14.21 ms **还含 preprocess**，
  Halcon 只算 `find_ncc_model`。两项都对本项目不利，能打出 1.36× 说明**单位工作量效率已接近**。
- 与第六节单图 360° 的结论一致：真正拉开差距的是**旋转模板物化成本**，
  角度网格越大差距越大（360° 冷帧曾慢到 2~3 倍），±10° 这种小网格只剩 1.36×。

### 7.5 结论

1. **NCC 与 Halcon 在本数据集上基本等价**：分数 r = 0.998、均值差 0.0005、
   位置差 0.11 px、角度差 0.09°。
2. **NCC 的得分口径可稳定对标**：负样本也稳定在 0.65~0.72，没有形状匹配那种
   "负样本 0.9 虚高"（`scoreMode=1`）的问题。
3. **差距主要在速度**，且是"物化旋转模板"的架构差；小角度网格 1.36×，大角度网格更大（见第六节）。
4. 与十四节 75 张抽样的结论一致（高置信子集 Δ 0.0006、位置差 0.13 px），抽样翻倍后未变化。

## 八、复现命令

```powershell
cmd /c tools\build-halcon-ncc.bat
$env:PATH='D:\Develop\Halcon17\bin\x64-win64;'+$env:PATH; $env:HALCONARCH='x64-win64'

# 双方同参数、各跑 5 次取最好

    --halcon-threads 1 --ours-threads 1 --repeat 5

# 我们自己的分段计时（含每层 rotTpl/score 拆分）
```

> 的 `search=` 字段**（进程内没有 Halcon 干扰）。
