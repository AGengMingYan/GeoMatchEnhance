# 抽样对比：本项目 vs Halcon 17（2026-11-14 复测，同模板同参数）

> 目的：用**同一模板、同一批抽样图、尽量一致的参数**，重新评估本项目 Shape / NCC
> 与 Halcon 17 Shape / NCC 的差距（Shape 侧已含 `skipWeight` 修复）。
>
> 采集：`tools/compare-sample.ps1`（本轮新增）　汇总：`tools/analyze-sample.ps1`
> 原始数据：`_ai_tmp/sample.csv`（95 行，不入库，重跑即得）
>
> 上一轮（修复前）的完整四器报告见 `docs/data1-data2四器对比报告.md`。

## 一、口径与前提（必读）

| 项 | 设置 |
|---|---|
| 模板 | data1 `template_pad.jpg`（140×140 焊盘）；data2 `template_via.jpg`（110×110 通孔） |
| 模型 | **本轮用同一模板重建**：本项目 `.shm/.ncm` 与 Halcon `.shm/.ncm` 都由同一 jpg 生成 |
| 角度范围 | data1 ±10°；data2 ±100°（按实测目标朝向） |
| 尺度 | 1.0（无尺度搜索） |
| minScore / maxMatches / maxOverlap | 0.5 / 1 / 0.5 |
| 极性 | 双方都是 use_polarity（本项目 `metric=0`） |
| 亚像素 | 双方开启（本项目 `subpixel=1` 抛物线；Halcon `SubPixel=true`） |
| 贪心度 | 双方 0.9 |
| 金字塔 | 双方自动 |
| 抽样 | data1：按文件名排序**等距取 59 张**（117 张的一半，覆盖全部亮度/模糊梯度）；data2：**全量 36 张** |

**两处不对等（速度结论必须带这两条前提）**：
1. **架构**：Halcon 侧本机只有 32 位 SSE2（`HalconDemo/Halcon17/x86sse2-win32`），
   本项目是 64 位 AVX2。
2. **计时口径**：本项目 = `preprocess + search`；Halcon = `find_*` 仅搜索。

## 五、耗时（ms，全部图；口径见第一节）

| 数据集 | Shape 本项目 | Shape Halcon | NCC 本项目 | NCC Halcon |
|---|---|---|---|---|
| data1 mean / p50 | 39.66 / 39.20 | **6.25** / 5.57 | **7.78** / 7.42 | 9.73 / 8.99 |
| data2 mean / p50 | 31.36 / 31.50 | **5.82** / 5.74 | 20.68 / 19.67 | **14.72** / 14.35 |

> - **Shape 慢 5~6×**（32 位 vs 64 位 + 点数/扫描策略差异）。
> - `skipWeight` 的耗时代价由 A/B 实测（data1 同 20 张、同模型）：
>   `-skip-w 0.9` 38.25 ms vs `-skip-w 0` 35.23 ms → **+8.6%**；
>   同期分数 0.903 vs 0.664（就是这项修复的价值）。
> - **NCC 小角度（data1）本项目反而更快**（7.8 vs 9.7 ms）；大角度（data2，201 个角度）
>   慢 1.4×（Halcon 预计算模型 2.67 MB，本项目 28 KB）。

## 六、负样本与阈值是否可共用

负样本集：**data1 模板（焊盘）× data2 的 36 张图**（画面里没有焊盘），
`minScore` 取 0.2 以便看到全部假分数：

| | n（>=0.2） | mean | p90 | **max** |
|---|---|---|---|---|
| Shape 本项目 | 36 | 0.338 | 0.390 | **0.403** |
| Shape Halcon | 15 | 0.307 | 0.352 | **0.362** |

对照真值最低分：本项目 data1 0.680 / data2 0.530；Halcon data1 0.622 / data2 0.568。

**结论**：两边的"真值下限 − 假值上限"间隔都在 **0.13~0.28**，
**minScore 取 0.50~0.55 对双方都安全**（假值 max 0.40，本项目的 data2 有 1 张真值 0.53
刚好过线）。修复前本项目假值 max 0.444、真值下限 0.505 —— 间隔只有 0.06，
阈值几乎不可用；现在与 Halcon 同一量级。

## 七、结论（一句话版）

| 维度 | Shape（本项目 vs Halcon） | NCC（本项目 vs Halcon） |
|---|---|---|
| 检出率 | data1 打平（59/59）；**data2 反超（35 vs 29）** | 打平（59/59、36/36） |
| 同实例分数差 | **0.073（data1）/ 0.029（data2）** | **0.0017 / 0.0014** |
| 定位（同实例） | **0.52 px（data1）/ 1.04 px（data2）** | **0.19 px / 0.56 px** |
| 角度 | 0.37~0.59° | 0.08~0.37° |
| 阈值 | 可与 Halcon 共用（0.50~0.55，间隔 0.13~0.28） | 需按数据标定：data2 真值最低 0.624，而历史负样本可到 0.65~0.72，**建议 0.7+ 并配合 minCoverage** |
| 速度 | 慢 5~6×（架构 + 策略，`skipWeight` 占 +12%） | 小角度更快（7.8 vs 9.7 ms）、大角度慢 1.4× |

**Shape 的定位结论**：`skipWeight` 修复后，分数口径已与 Halcon 对齐（差 0.03~0.07，
且逐图 gap 的上限只有 0.13），**可以直接按 Halcon 的经验阈值（0.5~0.6）使用**；
剩余差距集中在**速度**（5~6×）与**亚像素定位精度**（0.52 vs 0.19 px，仍属亚像素级），
不再有"系统性分数偏低导致漏检"的问题。

## 八、复现

```powershell
# data1：等距抽样（117 -> 59），分两批（每批 30 张，避免单次执行超时）
powershell -ExecutionPolicy Bypass -File tools\compare-sample.ps1 -Sets data1 -Stride 2 -Take 30 -RebuildModels -OutCsv _ai_tmp\sample.csv
powershell -ExecutionPolicy Bypass -File tools\compare-sample.ps1 -Sets data1 -Stride 2 -Offset 30 -Take 30 -Append -OutCsv _ai_tmp\sample.csv

# data2：全量 36 张
powershell -ExecutionPolicy Bypass -File tools\compare-sample.ps1 -Sets data2 -RebuildModels -Append -OutCsv _ai_tmp\sample.csv

# 汇总（检出/分位数/相关性/同实例一致性/耗时/data2 分簇）
powershell -ExecutionPolicy Bypass -File tools\analyze-sample.ps1 -Csv _ai_tmp\sample.csv
```

> `-RebuildModels` 会用同一模板重建双方四个模型（本项目 `.shm/.ncm`、
> Halcon `.shm/.ncm`），保证两边模型来源一致。
> 复现前提：`dataset/data1`、`dataset/data2` 的图片（不在仓库内）、
> `build/GeoMatchDemo.exe`、`build/NccDemo.exe`、`HalconDemo` 两个对比 exe 与 Halcon17 SDK。
