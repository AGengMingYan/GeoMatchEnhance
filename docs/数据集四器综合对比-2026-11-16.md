## 2. 采集方法

```powershell
# 示例：data1 全量四器采集（会同时建四个模型）
powershell -ExecutionPolicy Bypass -File tools\compare-dataset.ps1 `
    -Set data1 -Template dataset\sample\data1\template_pad.jpg `
    -Dir dataset\sample\data1 -AngleStart -10 -AngleExtent 20 -MinScore 0.5 `
    -RebuildModels -OutCsv _ai_tmp\ds_data1.csv

# 汇总（检出率 / 分数分布 / 同实例 Δscore Δangle Δpos / 耗时 / 合成真值误差）
python _ai_tmp\ds_analyze.py
```

脚本对每张图依次跑四个匹配器，按 `set,img,gN,gScore,gX,gY,gA,gK,gMs,nN,...,kN,kMs` 写一行 CSV；
`-Dir` 也可以直接给**单个文件**（多实例/大图用例就是这么跑的）。
`-Offset/-Take/-Append` 用于分片，避免单次执行超时。

## 3. 结果

### 3.1 data1（6 张，焊盘，±10°，对比度 120/160）

| 匹配器 | 检出 | 分数 min / 中位 / 平均 / max | 平均耗时 |
|---|---|---|---|
| 我们 Shape | 6/6 | 0.886 / 0.970 / **0.961** / 1.000 | 44.7 ms |
| 我们 NCC | 6/6 | 0.950 / 0.974 / **0.974** / 1.000 | 11.7 ms |
| Halcon Shape | 6/6 | 0.683 / 0.971 / **0.924** / 0.979 | 7.9 ms |
| Halcon NCC | 6/6 | 0.973 / 0.982 / **0.983** / 1.000 | 10.4 ms |

同实例（两点距离 < 15 px）差值：

| 对比 | 同实例对数 | Δscore 平均 / |Δ| | Δangle 平均 / max | Δpos 平均 |
|---|---|---|---|---|
| Shape 我们 − Halcon | 4（另 2 张选到不同焊盘实例） | −0.003 / 0.004 | 0.07° / 0.20° | 0.64 px |
| NCC 我们 − Halcon | 4（同上） | −0.001 / 0.001 | 0.07° / 0.12° | 0.18 px |

> 焊盘在画面里重复出现十几次，`max=1` 时两器可能选**不同物理实例**（历史报告已说明），
> 位置差不可直接比较；同实例上两者几乎完全一致。

### 3.2 data2（8 张，通孔，−100°..+100°，对比度默认 12/30，minScore 0.4）

| 匹配器 | 检出 | 分数 min / 中位 / 平均 / max | 平均耗时 |
|---|---|---|---|
| 我们 Shape | **7/8** | 0.437 / 0.905 / 0.723 / 0.995 | 47.9 ms |
| 我们 NCC | 8/8 | 0.624 / 0.952 / 0.857 / 1.000 | 20.8 ms |
| Halcon Shape | **7/8** | 0.472 / 0.970 / 0.804 / 0.990 | 9.9 ms |
| Halcon NCC | 8/8 | 0.624 / 0.954 / 0.878 / 1.000 | 24.5 ms |

- Shape 我们与 Halcon **各漏 1 张，但不是同一张**：
  我们漏 `scan_1776336136494_score.jpg`（NCC 在该图 0.912、Halcon Shape 0.629，
  说明目标在，但形状特征被斑纹破坏），Halcon 漏 `scan_1776336639895_score.jpg`
  （我们 0.442、NCC 0.640）；两种“失败模式”正好互补，整体检出率相同；
- 分数平均差 −0.040，同实例 Δangle 0.23°；
- NCC 同实例 Δscore **−0.001**、Δangle 0.12°、Δpos 0.30 px，仍是等价关系；
- 8 张里 4 张是 −90° 簇：我们 Shape 0.437~0.654、Halcon Shape 0.472~0.575，量级一致。

> 若把对比度也提到 120/160（`ds_data2.csv`）：Shape 双方都变成 6/8、NCC 不变 8/8，
> 分数整体抬高（我们 0.869 / Halcon 0.853）。**对比度是数据集相关参数**（见 §3.3）。

### 3.3 对比度敏感性（同一批图、只改建模阈值）

| 数据集 | 模型对比度（我们 Sobel / Halcon 灰度） | 我们 Shape 平均分 | Halcon Shape 平均分 | 差距 |
|---|---|---|---|---|
| data1 | 12/30（CLI 默认 = 灰度 3/7.5） | 0.679 | 0.945 | **−0.266** |
| data1 | **120/160（= 灰度 30/40）** | **0.961** | 0.924 | +0.037 |
| data2 | **12/30（默认）** | 0.723（7/8） | 0.804（7/8） | −0.081 |
| data2 | 120/160 | 0.869（6/8） | 0.853（6/8） | +0.016 |

结论：
- **锐边、高对比目标（data1 焊盘）必须提高对比度**（GUI 灰度差 30 / 高阈值 40），
  否则模型混进大量弱边点，全点平均被拉低 0.27；
- **低对比、斑纹目标（data2 通孔）不能提高**，会把 −90° 簇的真目标一起截掉（7/8 → 6/8）；
- 两项调参口径：GUI 灰度差 ×4 = CLI `-contrast/-hi`（Sobel），Halcon 直接用灰度值。

### 3.4 synth（80 张合成样本：16 角度 × 5 缩放，真值写在文件名）

| 匹配器 | 检出 | 分数 平均 | 角度误差 平均 / max | 尺度误差 平均 / max | 平均耗时 |
|---|---|---|---|---|---|
| 我们 Shape | **80/80** | 0.903 | **0.068° / 0.27°** | 0.0022 / 0.0050 | 314 ms |
| Halcon Shape | 80/80 | 0.956 | 0.113° / 0.36° | 0.0015 / 0.0069 | 21 ms |
| 我们 NCC | 61/80 | 0.592 | 无效（见下） | —（NCC 无尺度） | 36 ms |
| Halcon NCC | 64/80 | 0.593 | 无效（见下） | — | 9.6 ms |

- Shape：检出、角度、尺度全部与 Halcon 同量级，**角度精度我们略好（0.068° vs 0.113°）**，
  分数系统低 0.053（与历史报告的 0.05~0.07 一致）；
- NCC 双方都**没有尺度维度**：缩放到 0.70/1.30 时会把目标当成别的尺寸去匹配，
  于是检出掉到 61/80、64/80，且“角度误差”失去意义（角度是按错尺寸最优位姿算出来的）。
  **有尺度变化的目标不要用 NCC**，这是算法维度问题，不是实现差距；
- 耗时：360° × 49 个尺度，我们 314 ms / Halcon 21 ms，差距主要来自尺度网格的逐尺度卷积
  （Halcon 8 位整数 + SIMD，见历史性能分析）。

### 3.5 dataset/image 多实例 / 多尺度 / 大图

| 用例 | 我们 Shape | 我们 NCC | Halcon Shape | Halcon NCC | 耗时（我们 S/N / Halcon S/N） |
|---|---|---|---|---|---|
| 齿轮 `m3` → `retainers_02`（360°） | 5 | 5 | 5 | 5 | 27.5/99.5 ms，7.9/26.4 ms |
| 卡簧 `m1` → `rings_02` | 3 | 2 | 4 | 4 | 40.7/71.0 ms，15.9/13.5 ms |
| 螺母 `m4` → `nuts_01`（尺度 0.4~1.7） | **14** | 4 | **14** | 7 | 788/297 ms，42.6/12.2 ms |
| logo `m2` → `green-dots` | 1 | 1 | 1 | 2 | 111/218 ms，77.2/10.8 ms |
| 齿轮 `m3` → `qfn1`（2448×2048，无目标） | 0 | 0 | 0 | 0 | **251.8/2552 ms**，6.2/32.1 ms |

- **多尺度螺母**：Shape 14/14 与 Halcon 完全一致（分数都 0.999），代价是 788 ms vs 42.6 ms；
  NCC 没有尺度维度，4/7 个只是“恰好同尺寸”的实例；
- **卡簧 `rings_02`**：我们 3（NCC 2）< Halcon 4。该图是“卡簧+齿轮混放”，Halcon 的第 4 个落在
  齿轮上（历史 README 也记过 0.78 的齿轮误检）。属于**密集重复场景的取舍差异**，

- **大图 NCC 是明显短板**：2448×2048、360° 时我们 2552 ms（Halcon 32 ms）。
  原因是逐角度、逐金字塔层的全图 NCC；实用做法是收窄角度或用 Shape（251.8 ms）。

### 3.6 负样本（模板与数据集错配，minScore 0.3）

| 组合 | 我们 Shape | 我们 NCC | Halcon Shape | Halcon NCC |
|---|---|---|---|---|
| 焊盘模板 → 通孔图（8 张，目标不存在） | **0/8** | 8/8，平均 0.578（max 0.654） | **0/8** | 8/8，平均 0.579（max 0.655） |
| 通孔模板 → 焊盘图（6 张） | 6/6，平均 0.453（max 0.489） | 6/6，平均 **0.701**（max 0.732） | 5/6，平均 0.394 | 6/6，平均 **0.703** |

- 两种模板本身长得像（白块 + 暗孔），所以 **NCC 的错配分能到 0.70，且两个引擎数值几乎相同**
  （Δ ≤0.002）——这是 NCC 本身的性质，不是我们的缺陷；
- 推论：**用 NCC 时 minScore 不能设 0.5~0.6**，重复/相似纹理场景建议 ≥0.75，
  或先用 Shape 做交叉确认；Shape 在同样错配下只有 0.39~0.45（我们）/0.36~0.46（Halcon）。

## 4. 极端参数鲁棒性

### 4.1 方法

`_ai_tmp/extreme_cases.ps1` 把「用户可能拖到/写错的极端参数」直接喂给两个 CLI，
记录 **退出码 + 墙钟时间 + 判定**：

- `CRASH` 只认真正的进程死亡：`0xC0000409`（-1073740791）、`0xC0000005`（-1073741819）、
  `0xC00000FD`（栈溢出）、`0xC000001D`，或输出里出现 `Assertion failed` / `terminate called`；
- `exit = -1` 是 CLI 的 `return -1`，属于**优雅拒绝**（有错误信息），不算崩溃。

```powershell
powershell -File _ai_tmp\extreme_cases.ps1                       # build\   (x64)
powershell -File _ai_tmp\extreme_cases.ps1 -BuildDir build_x86 -Tag x86
```

### 4.2 结果：67 例 × 2 架构 = **0 崩溃**

| 构建 | ok（exit 0） | rejected（exit −1） | CRASH |
|---|---|---|---|
| x64（`build\`） | 58 | 9 | **0** |
| x86（`build_x86\`） | 58 | 9 | **0** |

9 个「优雅拒绝」：`contrast=1e6`（模型点数为 0）、`1×1` 模板、纯色 `64×64` 模板、
模板文件不存在、模型文件不存在/损坏、搜索图不存在、搜索图不是图片（后两者是本轮新修，见 §4.4）。

**被正确限制、没有跑飞/崩溃的重点用例**：

| 用例 | 结果 |
|---|---|
| 尺度 `8..9`、`1..9.1`、`0.01..10` | exit 0；`8..9` 报 0 命中，另两个正常命中（历史版本会 abort） |
| 尺度 `0..0`、`-2..-1` | exit 0，0 命中 |
| 尺度反序 `2..1` | exit 0，按 1..2 处理，正常命中 |
| 角度 `0`、`720`、`-20` | exit 0；720° 正常出结果（63 ms） |
| `levels 99` / `-1` | exit 0，自动收敛到可用层数 |
| `points 0`（不限点数）、`chain 0/1000` | exit 0 |
| `max 0` → 0 命中；`max 100000` → 1 命中 | exit 0 |
| `min-dist -5`、`skip-w 5`、`cell-miss 2`、`score-mode 9` | exit 0，参数被钳制，不崩 |
| 模板比搜索图大（`m1` 207×185 → 8×8） | exit 0，0 命中，search 0.0 ms |
| **5M 像素模板**（`qfn2` 2448×2048） | 建模型 1200 点 / 7 层 / 398.7 ms，exit 0 |
| 5M 像素图上 360° Shape 搜索（`points 0`） | 74 ms，exit 0 |
| NCC：`1×1`、纯色、32×32 模板 ×360° | 建模/搜索都 exit 0（0 命中） |
| NCC：`levels 99/-1`、`angle 720`、`metric 9`、`minscore 1.0`、`max 0/100000`、`overlap 2/-1/0` | 全部 exit 0 |

### 4.3 Halcon 17 对照（`_ai_tmp/halcon_extreme.ps1`）

| 用例 | Halcon 结果 | 我们 |
|---|---|---|
| 尺度 `0.01`（缩放后短边 1.4 px） | **#8510 points too small**，exit 1 | exit 0，0 命中 |
| 尺度 `8..9` | **#3513 internal error: number of chords too big**，exit 1 | exit 0，0 命中 |
| `1×1` / 纯色模板（Shape） | #8510 points too small，exit 1 | exit −1（建模型失败） |
| 对比度 `1e6` | #3100 wrong segmentation threshold，exit 1 | exit −1（建模型失败） |
| `levels 99` | #1301 wrong value of control parameter 1，exit 1 | exit 0（自动收敛） |
| 模板比图大 | exit 0，0 命中 | exit 0，0 命中 |
| `angle 720` | exit 0 | exit 0 |
| NCC `1×1` 模板 | #8506 template points too small，exit 1 | exit 0（0 命中） |
| NCC `overlap 2` | exit 1（参数非法） | exit 0（钳制后正常） |
| 缺失模板 / 缺失图 | #5200 file not found / 读图失败，exit 1 | exit −1 |

> 结论：**两边都不会因为极端参数让进程消失**，但处理风格不同 —— Halcon 用 HException
> 明确拒绝非法参数（甚至「尺度 8..9」这种在它看来无法建模型的范围），
> 我们更倾向于「钳制到可用范围后照常返回（可能 0 命中）」。

### 4.4 本轮修掉的问题：输入不可读时静默返回 0

修复前（实测）：

```
build\GeoMatchDemo.exe -t pad.jpg -s nope.jpg ...   -> 只打印 OpenCV WARN，exit 0
build\NccDemo.exe -load x.ncm -s nope.jpg -nodraw   -> 只打印表头，exit 0
```

这与「图有效但 0 命中」无法区分，脚本会把“路径写错”当成“没找到目标”。已改为：

```
no readable image to search: nope.jpg            (Shape)
[ncc] no readable image to search (1 path(s) given)  (NCC)
exit -1
```

只影响错误路径（`-d` 目录为空 / 全部图读不出时同样生效），正常匹配结果不变
（data1 6/6、scores 与修复前逐位一致）。

## 5. 结论与建议

1. **NCC 与 Halcon 可以互认**：三个数据集上同实例 Δscore ≤0.003、Δangle ≤0.4°、Δpos ≤0.8 px；
   分数阈值可以照 Halcon 的口径直接迁移。
2. **Shape 的分数水平比 Halcon 低 0.05（合成）/ 高 0.02（真实焊盘）**，
   角度精度反而更好（0.068° vs 0.113°），检出率在三个数据集上与 Halcon 完全同档。
3. **参数是数据集相关的**：锐边高对比目标把对比度提到灰度 30/40（CLI 120/160）；
   低对比斑纹目标保持默认（灰度 3/7.5）。用错方向会同时损失 0.27 分或 1/8 召回。
4. **有尺度变化时用 Shape，不要用 NCC**（NCC 无尺度维度：80 张合成里只检出 61/80）。
5. **大图 + 大角度优先 Shape**：2448×2048、360° 时 Shape 252 ms、NCC 2552 ms。
6. **NCC 的 minScore 要提高**：相似纹理错配能到 0.70（Halcon 同样），不要用 0.5~0.6。
7. **极端参数不会崩溃**（x64/x86 各 67 例 0 crash）；输入不可读现在会明确报错退出。
